# 04 — Interface

Owner: C (screens), with A for English and Bangla copy. Every user-visible string comes from `config/i18n/{en,bn}.json` or the catalog; components hard-code no text. Every number comes from a result file written by the engine. Components format numbers and lay them out. They compute nothing: no slope, no mean, no p-value, no interval (AGENTS.md rule 2).

---

## 1. Principles

1. **Answer first, detail on demand.** Each screen leads with one plain sentence; the statistics sit under "For experts".
2. **One decision per step.** Question, place, then the answer. Each choice can change without losing the others.
3. **Status before numbers.** Every result shows first whether it is a verdict, "can't tell yet", "no verdict" (with the reason), exploration or a sensitivity check, and which family it belongs to.
4. **Never a bare number.** Every number has units, a time span and a one-line meaning.
5. **Detective, lightly.** Words like case, checks and verdict structure the story, with no cartoon props that slow the page or talk down to students.
6. **Phone first, Bangla first-class.** Layouts work at 360 px wide and with Bangla text that runs 20–40% longer.

---

## 2. Routes (hash routing; works on static hosting and from `file://`)

The view is in the URL hash (`schemas/view.schema.json`; 01 §6), so every view can be shared.

| Route | Screen | Scope |
|---|---|---|
| `#/` | Home | — |
| `#/question?question=<id>` | Question cards, shortlist and record cards | M1 |
| `#/place?region=<id>&variable=<v>&season=<s>` | Place: picker, line-up, verdict | M2, M3, M4, M5, M7 |
| `#/place?region=cell:<row>_<col>&variable=<v>&season=<s>` | Cell page (exploration only) | M8 |
| `#/compare?pair=<id>&variable=<v>&season=<s>[&sensitivity=imerg]` | Compare two places | M6, S3 |
| `#/map?variable=<v>&season=<s>` | Screening map | M8 |
| `#/watch/<case>` | Watch a case | S2 |
| `#/methods` | Methods (one page) | M9 |
| `#/offline` | Cases kept on this device | M10 |
| `#/data` · `#/ai` · `#/about` | Data & credits · AI use · About | M9 |

The language toggle (English or Bangla) is kept in `localStorage` (inside try/catch) and set on `<html lang>`. It never changes the URL, so links work in both languages.

## 3. Layout

**Desktop (≥ 1024 px):** header 56 px; the confidence spine (S5) under the header whenever a result is on screen; content in two columns: the chart (left, flexible) and the verdict or compare card (right, 420 px).

**Tablet (768–1023 px):** one column: chart, then card.

**Phone (< 768 px):** one step per view, with a sticky bottom bar (Back · Next, 44 px targets); the spine sits above the bottom bar; the map is a collapsible panel of 45% of the screen height. There is never horizontal scrolling.

Header: name, navigation (Ask a question · Compare two places · Screening map · Watch a case · How we know), language toggle. Footer: "Built with NASA data: MERRA-2 (model) and GPM IMERG (satellites and gauges)" as text, never logos; Data & credits; AI use; source code; "Cases on this device".

## 4. Screens

### 4.1 Home
- Hero title and body (`home.hero_*`), the learning-goal line (`home.learning_goal`) and three buttons: Ask a question · Compare two places · Watch a case first.
- The lead case card (`cases/lead_contrast_rain.json`): title, one-line summary, ▶.
- "Where is it changing?" links to the screening map.
- No background video and no image from another site. Everything ships with the build.

### 4.2 Question (M1)
- Question cards from the catalog (`config/questions.yaml`): `place` questions lead to the place picker, `compare` questions to the pair picker.
- Each card opens its **shortlist**: one row per variable with the reason it fits (`why`) and its **record card**:
  - record: first and last year used;
  - gaps;
  - known breaks (documented data changes), each with its date or "gradual";
  - observation or model (badge: Model · Satellite · Observations · Sensitivity check);
  - what it cannot answer.
- Deferred variables (`also_deferred`) show their cards greyed, labelled "Not analysed in this release", and cannot be opened as cases.

### 4.3 Place picker (M2)
- Three lists: Bangladesh; Divisions of Bangladesh; Comparison regions. A division that failed the support rule is listed and greyed with `place.not_in_set`.
- "Or pick any 1° cell on the screening map" opens the map.
- After a choice: the outline on the map and the **contributing cells** shaded by their fraction inside the region (`regions/cells/<grid>/<region>.json`), with `place.support` ("N data cells cover this place").

### 4.4 Line-up (M3)
- Intro line `lineup.intro` with the number of tests on the screen.
- One row per variable and season (`ANN` first, then the pre-registered seasons): rate per decade with its 95% range, the family badge, and the adjusted p (Holm or Benjamini–Hochberg). Exploration rows show "adjusted within this list of N" (`lineup.adjusted_within`).
- A row opens its verdict. Every row shows its status, so a "no verdict" row is never mistaken for a weak verdict.

### 4.5 Verdict card (M4, M5, M7; S1, S4)
Top to bottom (`aria-live="polite"`):
1. **Status badge:** the grade (Strong evidence · Supported trend · Can't tell yet), or "No verdict" with its reason, or "Exploration", or "Sensitivity check". Icon plus words, never colour alone. Next to it, the family badge (Pre-registered test · Secondary (seasons) · Exploration · Sensitivity check).
2. **Headline:** `text.<lang>.headline` from the result. For "can't tell yet" it always ends with "That is not the same as no change."
3. **Chart** (§6.1): yearly values on actual years, the Sen line, the range band and the documented data changes.
4. **How much?** `text.howMuch`: rate per decade with its 95% range, total change (and percent of the starting level for rain), and the signal-to-noise sentence.
5. **How sure?** `text.howSure`: the family sentence with the family size and the adjusted p; MK-AR1 before correction; whether p is below the pre-set line.
6. **Can we break it?** `text.checks`: gaps, coverage, documented breaks with their review, leave-one-year-out, the five other windows (labelled "robustness checks, not new claims"), and the Pettitt flag (S4: "a flag only: it does not change the verdict").
7. **Is it big enough to matter?** `text.practical`.
8. **What would overturn this claim?** (S1) `text.overturn`, at most three items, shown only on verdicts.
9. **Notes** `text.notes` (for example, the model note).
10. **Where these numbers come from:** the provenance panel (§4.10).
11. **For experts** (collapsed): S, tie-corrected Var(S), τ, Z and p with its `pKind`; φ̂, φ̃ and VIF; Var\*(S), Z\* and p\*; Sen slope and intercept per year; the widened range (multiplier 2.25); the t-test (labelled "shown for comparison; it does not decide", or "unavailable" when n_eff ≤ 3); the naive test (labelled "ignores year-to-year memory"); domain checks D1–D7 with their values and limits; the leftover-memory statistic and its critical value; a link to the result file.

The card never shows a "years needed" number. **Outside the domain** it shows the slope and `reason.outside_domain`, with no band and no grade; the expert panel marks the interval "not calibrated here".

### 4.6 Compare (M6; S3)
- **Pair picker:** pre-registered pairs first (the lead pair marked), then any two places from the region set. Pairs that are not pre-registered are exploration. Cells cannot be paired.
- **Title:** "Trend in the difference (A − B)" (`contrast.estimand`).
- **Chart** (§6.2): both regions' yearly values, and below them the difference series with its own trend line and band.
- **Headline:** `text.headline`, worded by the labels: "rates differ", "can't tell yet … not the same as no difference", exploration or no verdict.
- **Each place on its own:** `contrast.side`, both rates with their ranges and statuses, and `contrast.not_subtracted` ("shown beside the difference, never subtracted from it").
- **Labels**, each shown only when true and with its meaning: opposite fitted directions (`contrast.opposite_fitted`: "on its own that does not show the trends differ"), supported opposite trends, rates differ.
- The checks, practical threshold, overturn rules and provenance of the difference, as on the verdict card.
- **IMERG sensitivity check (S3):** a toggle (`sensitivity.toggle`) shows the same comparison on IMERG over 1998–2024 beside MERRA-2 over the same years, with the lineage line (`sensitivity.lineage`) and the same-sign or opposite-sign sentence. It never shows a grade.

### 4.7 Screening map (M8)
- Variable and season selectors (`ANN` and the pre-registered seasons).
- Canvas map (§7): colour = rate per decade on a diverging scale symmetric around zero, limits from `colourLimit`; a dot on cells that stand out after Benjamini–Hochberg at q = 0.10 within the map; **hatching** on cells that cannot be tested, with the reason from the flags on hover or tap.
- Always visible: the label "Screening map: exploration, not a verdict" (`map.label`) and the number of tests (testable cells).
- Picking a cell opens its cell page.

### 4.8 Cell page (exploration)
- The cell's yearly values from its cell tile, and from the map file its rate, range, p and q.
- The status is always "Exploration" (`cell.exploration`). No verdict words, no grade.
- No trend line: the map file holds no line, and the site does not compute one.
- The 5 × 5 neighbourhood used for its memory check is outlined on the mini-map.

### 4.9 Methods (M9; one page)
Sections, each from a result file: where our verdicts are valid (D1–D7 and the φ_max(n) table); stress tests; our pre-registered tests (the confirmatory and secondary families, with the pre-registration's SHA-256 and commit); false alarms when nothing changes (calibration); how often the 95% range catches the true rate (coverage); what a record this long can detect (the power table and, per confirmatory test, `methods.power_sentence`); tests that guard the code (golden suites and their result in this build); the exact input files (manifest summary and SHA-256); documented data changes and their reviews.

Every rate is worded as a property of the method (`methods.property`): "With no trend, it flags about 6 in 100 such records. This describes the method, not the chance that a verdict on this site is wrong."

### 4.10 Provenance panel (M9)
On every result: dataset (name, short name, version, DOI), years used, values used and missing, route, build id, pre-registration SHA-256, input-manifest SHA-256, engine version and config hash, and a link to the result file itself.

### 4.11 Watch (S2)
**WatchPlayer** over the normal screens: a caption bar (bottom, two or three lines), progress dots, Play · Pause · Previous · Next, and "Investigate this yourself", which leaves the player on the same view. Each beat sets the view, spotlights one element (dimmed backdrop, focus ring) and shows its caption, filled by the engine from the result files. The case's `ending` (`supported` or `cant_tell_yet`) picks the verdict beat. Default beat length 6 s; `prefers-reduced-motion` turns off transitions, and steps still advance.

### 4.12 Cases on this device (M10)
`#/offline` lists the cases in `offline/set.json`: count, titles and the files each uses. In the offline build this list is the home screen's second section, and the offline banner shows whenever a view needs a file that is not on the device.

### 4.13 Data & credits, AI use, About
Static pages. Data & credits lists the citations of 02 §12. AI use shows the statement from `docs/AI_USE.md` §1. About shows the team and the licences.

## 6. Charts (Observable Plot)

Charts draw what the engine wrote in the result's `chart` block (`schemas/verdict.schema.json`, `contrast.schema.json`): display values, the Sen line as two end points, and the range band as two segments through the pivot. The site does no arithmetic on them beyond scaling to pixels.

### 6.1 TrendChart (verdicts)
- x: actual years. Yearly or seasonal values as dots joined by a line; missing years are gaps, never interpolated.
- The Sen line (`chart.line`), solid for a verdict and dashed for "can't tell yet", exploration and sensitivity results. The band (`chart.band`) as a light bow-tie, drawn only when the engine wrote one (never outside the domain).
- Documented data changes in the window as vertical dashed rules labelled "data change"; reviewed ones carry the review outcome.
- The Pettitt year, when flagged, as a small marker labelled "jump?" (S4).
- y-axis with units. Text alternative: the headline.
- Toggle "Every month": the monthly values from the series file, as a thin grey line, for display only.

### 6.2 DifferenceChart (compare)
- Top panel: A and B on one y-axis, two lines with direct labels, each with its own Sen line from its verdict's `chart`.
- Bottom panel: the difference A − B as departures from its window mean (`chart.values`, `chart.offset`), with its Sen line and band, and a zero line. Title "Trend in the difference (A − B)".

### 6.3 Map colours and numbers
Diverging scales symmetric around zero (from the catalog's `colormap.trend`, implemented with `d3-scale-chromatic`); hatching as a 45° pattern at 30% opacity; colour-blind-safe palettes. Numbers use tabular figures (`font-variant-numeric: tabular-nums`).

## 7. Map (canvas, equirectangular)

1. **Base:** Natural Earth outlines, simplified and bundled (`web/public/outlines/world_110m.json`). No tile server, no imagery from another site (ADR-08), so the map works offline and under the Content Security Policy.
2. **Projection:** equirectangular, so each 1° cell is a rectangle; zoom and pan on the canvas; on phones the map fits the width.
3. **Layer:** for each cell from `maps/<variable>/<season>/cells.bin.gz`, fill with the rate colour; a centre dot where flag bit 2 (significant) is set; hatching where bit 1 (testable) is clear.
4. **Places:** outlines of the fixed region set; on a place screen, the contributing cells shaded by fraction.
5. **Keyboard:** arrow keys move a cell cursor; Enter opens the cell page; the cursor's cell is announced (latitude, longitude, rate, status).

## 8. Accessibility (WCAG 2.2 AA)

- Keyboard: every card, list, toggle and button can be reached and used; a visible 3 px focus ring; Esc closes dialogs; the map has the keyboard cursor and the place lists as alternatives.
- Screen readers: `aria-live="polite"` on the verdict; charts have text alternatives; status icons have text.
- Colour: text contrast at least 4.5:1; status and significance never shown by colour alone; colour-blind-safe palettes.
- Motion: `prefers-reduced-motion` stops transitions.
- Language: `lang="bn"` on Bangla text; Noto Sans Bengali bundled and loaded in Bangla mode (`font-display: swap`).
- Touch targets at least 44 × 44 px.

Tests: X-01 (axe-core: no serious or critical violations), X-02 (keyboard only), X-05, X-06.

## 9. Language and copy

- Keys only: `t('verdict.labels.how_much')`. A missing key shows `⟦key⟧` in development and English in production, and CI fails on missing keys (X-04).
- Verdict, contrast and case sentences come already filled from the engine in both languages. The site's `format.ts` formats only numbers outside sentences (axis ticks, table cells), with the rules of 03 §12.3.
- Copy rules: sentence case; one idea per sentence; units always; verdict words only for confirmatory and secondary results; "consistent with", never "caused by"; define a term on first use (glossary tooltip). The wording table is 03 §12.1.
- Text expansion: check every screen in Bangla; nothing truncates; buttons wrap to two lines if needed.

## 10. States

| State | Show |
|---|---|
| Loading | Skeleton and "Loading results… (2 of 3 files)" |
| File missing | `errors.missing_file` in that panel; never zeros, never a guess |
| Results unreachable | `banner.results_unreachable`, and the offline list |
| Synthetic | `banner.synthetic` (cannot be dismissed) |
| Offline | `banner.offline` |
| Bad link | `errors.bad_view`, with defaults filled in |
| Error | `errors.generic` with an id, and "Copy details" for bug reports |

There is no "computing" state: nothing is computed in the browser.

## 12. Toolkit and the polish loop (ADR-17)

**Toolkit, used from Part 3 on:** Tailwind CSS configured with the tokens of §11 (no colour outside the tokens); shadcn/ui components copied into `web/src/ui/common/` (Radix primitives give keyboard and screen-reader behaviour); Lucide icons; Motion for transitions, always behind `prefers-reduced-motion`; Observable Plot for charts; Inter and Noto Sans Bengali bundled. Nothing is fetched at run time, so the offline file keeps working. Components that fit: Card, Tabs, Toggle Group (language, sensitivity), Dialog and Sheet (expert panel on phones), Tooltip (glossary), Table (line-up), Badge (status and family), Skeleton (loading).

**Polish loop (Part 6):**
1. Playwright saves a screenshot of every screen at 360, 768 and 1280 px wide, light and dark, English and Bangla (`npm run test:e2e -- --update-snapshots` writes them to `web/tests/screens/`).
2. Review the set against this checklist: one clear headline per screen; status badge before numbers; consistent spacing (4 px grid); no text below 14 px except axis labels; contrast at least 4.5:1; nothing truncated in Bangla; charts readable at 360 px; the spine visible and quiet; hatching distinguishable from colour.
3. Fix, then keep the screenshots as visual-regression baselines, so later changes cannot break the look unnoticed.
